# Practice-to-WordPress mapping

The [Authoritative Blog Article Distribution workbook](https://docs.google.com/spreadsheets/d/1M0arM4jnZzalySGUKq60Hp1yhTDz2RQTXqMeOWfaOUA/edit) is the editable source for location and WordPress-site assignments. Join `Locations.Code` to `Wordpress Sites.Codes`, and join each doctor's `Doctor Census.Primary Location` by its code in parentheses. The public URL in `Locations.URL` is **not** a WordPress API address.

As of the October 1, 2026 live reconciliation, the workbook produced 58 eligible general-dentist locations with complete, matching public-site and WordPress-site rows and 106 eligible full- or part-time general dentists. The locations map to 49 distinct WordPress editing subsites; all 49 URLs were also found in WordPress Network Admin's Sites list. `CO-08` through `CO-12` share `/co-08/`; `CTX-05` through `CTX-08` share `/ctx-05/`; and `HOU-05` through `HOU-07` share `/hou-05/`. This sharing is retained from the workbook, not inferred from a public website domain. Specialty codes, test/support locations, and the not-yet-launched `DFW-24` and `DFW-25` are excluded.

The initial [BigQuery mapping sync](../sql/initial-practice-site-mapping-2026-09-23.sql) staged those 58 rows in `apex-marketing-n8n.automated_article_creation.practices`. IDs are deterministic (`AZ-01` → `practice_az_01`). Each row has the public URL in `website_domain` and a JSON `publisher_config_reference` containing `location_code` and `wordpress_base_url`. On October 1, 2026, a fresh read-only audit confirmed that all 49 distinct WordPress REST endpoints returned the expected subsite path with no missing or mismatched endpoints. The 58 rows were then activated with `publisher_type = WORDPRESS`, the existing multisite credential reference, `mapping_status = VERIFIED`, and `verification_scope = WORDPRESS_ONLY_NO_STATIC_RELEASE`. The activation wrote one audit event per practice and did not create a post or call a Headless Hostman release. The existing TEST001 practice was not changed.

The SQL file is a dated initial snapshot, not a replacement for the workbook or a safe script to rerun after the workbook changes. The active `AAC - 25 - Sync Doctor Census` n8n workflow now reads only the bounded roster and mapping columns and reconciles them into BigQuery every hour. Doctor names, work emails, and primary-practice links follow the current eligible census; removed or ineligible census doctors are made inactive rather than deleted. New practices remain inactive with `mapping_status = UNVERIFIED`, and existing activation, credential, and verification settings are preserved. The sync never enables publishing. Never copy a public static URL into `wordpress_base_url` or place a password/application password in the sheet or repository.

`Apex Article Publisher` is the **application-password label** on the `jdold` WordPress user, not a separate WordPress account. `jdold` has multisite Super Admin rights, so the existing application password does not require a separate user-role grant on each subsite. The TEST001 posts show `jdold` as author. This is broad network-level access; the verified-practice guards in n8n and BigQuery practice settings, not WordPress roles, are the barriers against publishing to a real practice. Do not put this application password in the workbook or repository.

The production article-generation, doctor-review, revision, marketing-review, and marketing-revision workflows now accept only TEST001 or an active practice with a complete `WORDPRESS` configuration and `mapping_status = VERIFIED`. The five-day doctor auto-approval remains enabled. Marketing approval is still required before the WordPress publisher runs. Publishing to WordPress does not invoke the Headless Hostman static-site build or change the public practice website; that release remains manual. Before any future public/static release, separately verify Shortcoder output and location routing for the three shared-site groups (`CO-08`, `CTX-05`, and `HOU-05`).

The first controlled subsite check was Prestonwood (`DFW-03`). Its WordPress dashboard identifies the site as Prestonwood Family Dentistry, and its `practice_name` Shortcoder value matches. On September 23, 2026, the [isolated manual pilot](https://n8n.apexdentalautomation.com/workflow/x8P9o3fLDyDMxJ4s) used the existing n8n WordPress credential to create [internal test post 9987](https://apexparent.hostmanpowered.com/dfw-03/wp-admin/post.php?post=9987&action=edit). Both the API response and WordPress editor showed `draft`; the post has a fixed pilot slug and non-clinical integration-test copy. This proves credential write access to the multisite publishing layer, but it does not trigger a public/static release. Do not publish this pilot draft or use it as a patient-facing article.
